前端统一样式文件说明

目录结构
frontend/src/styles/
- tokens.css
- base.css
- ui.css


一、tokens.css 是什么
tokens.css 用来集中定义“设计变量”，也可以理解为整个产品的视觉参数总开关。

它主要负责：
1. 颜色
   - 页面背景色
   - 卡片背景色
   - 主文字颜色
   - 弱文字颜色
   - 边框颜色
   - 主按钮颜色
   - 错误提示颜色

2. 布局参数
   - 页面最大宽度
   - 页面上下左右留白

3. 圆角
   - 卡片圆角
   - 胶囊按钮圆角

4. 字体尺寸与行高
   - eyebrow 小标题
   - 正文
   - 大号正文
   - 标题
   - 移动端标题
   - 各类行高

为什么要有它
因为以后你想统一调整产品气质时，不应该去每个页面一个个改颜色、字号、圆角。
你只需要优先改 tokens.css，就能让整体风格一起变化。

一句话理解：
tokens.css 是“视觉参数中心”。


二、base.css 是什么
base.css 用来放“全局基础规则”。

它主要负责：
1. 全局 box-sizing
   - 让宽高计算更稳定，避免布局混乱

2. html / body / #app 的基础尺寸和默认边距
   - 保证页面铺满
   - 去掉浏览器默认 margin / padding

3. body 的基础视觉气质
   - 默认背景色
   - 默认文字颜色
   - 默认字号和行高

4. 表单元素继承字体
   - button、input、textarea 默认继承统一字体

5. 链接与 textarea 的一些基础行为
   - a 默认不带下划线
   - textarea 允许垂直拉伸

为什么要有它
因为有些规则应该是“整个项目都统一”的，而不是每个页面重复写一遍。
如果这些基础规则散在各个 .vue 文件里，后面会越来越乱。

一句话理解：
base.css 是“全局地基”。


三、ui.css 是什么
ui.css 用来放“可复用的界面样式类”。

它主要负责：
1. 页面壳层
   - .page-shell
   - .page-container

2. 文案层级
   - .ui-eyebrow
   - .ui-title
   - .ui-subtitle

3. 通用卡片和输入框
   - .ui-card
   - .ui-input

4. 按钮和操作区
   - .ui-actions
   - .ui-btn-primary
   - .ui-btn-secondary

5. 状态提示
   - .ui-status
   - .ui-error

6. 移动端适配
   - 标题缩小
   - 按钮纵向排列
   - 输入框高度调整

为什么要有它
因为你的产品是一个体验高度统一的问答/报告流程。
如果每一页都自己重新写一套按钮、标题、卡片、输入框样式，后面会很难维护。
ui.css 的意义，就是把这些重复结构抽成统一类，之后页面直接复用。

一句话理解：
ui.css 是“统一界面零件库”。


四、这三个文件之间的关系
可以这样理解：

1. tokens.css
定义参数
相当于：原材料和尺寸标准

2. base.css
打地基
相当于：房子的基础施工规范

3. ui.css
做界面零件
相当于：门、窗、桌子、椅子这些可复用部件

关系顺序是：
tokens.css → base.css → ui.css

也就是说：
先有变量
再有全局基础
最后有复用组件样式


五、为什么不直接全写在每个 .vue 文件里
因为你现在做的是一个需要不断调整体验的产品。
如果样式都散在各页面里，会出现几个问题：

1. 改一个颜色，要翻很多文件
2. 按钮风格容易不统一
3. 新页面会越写越乱
4. 后期做品牌感或作品感升级会非常麻烦

所以先把样式架构统一起来，是为了：
- 之后更快迭代
- 更容易统一风格
- 更容易把产品做精致


六、当前最适合的使用方式
现阶段最合理的做法不是一下把所有旧样式全删掉，而是：

1. 先在 main.js 中全局引入这三个文件
2. 新页面优先使用这些统一类
3. 旧页面逐步替换，不着急一次完成

这样风险最低，也最适合你当前“在旧项目上慢慢改”的策略。


七、后续建议
接下来最自然的动作是：

1. 在 main.js 里统一引入
   import './styles/tokens.css'
   import './styles/base.css'
   import './styles/ui.css'

2. 优先改 SelfValueLanding.vue、SelfValueIntro.vue、SelfValueQuestions.vue、SelfValueReport.vue
   让它们先吃统一样式

3. 以后如果想整体调产品气质，优先改 tokens.css
   而不是直接改页面文件


总结
- tokens.css：统一视觉变量
- base.css：统一全局基础规则
- ui.css：统一可复用界面样式
